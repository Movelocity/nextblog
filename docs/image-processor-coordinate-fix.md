# 图片裁剪坐标系统修复文档

## 📋 问题描述

之前的图片裁剪功能存在坐标系统不一致的问题，导致裁剪结果与裁剪框位置不匹配。

### 问题根源

存在三个不同的坐标空间，但它们之间的转换没有正确处理：

1. **容器坐标空间**（Container Space）- 包含 padding 的外层容器
2. **显示坐标空间**（Display Space）- 图片通过 `object-contain` 缩放后的实际显示尺寸和位置
3. **原始图片坐标空间**（Image Space）- 原始图片的像素尺寸

**错误示例**：
```
容器: 800x600px
原图: 3000x2000px
显示: 由于 object-contain，实际显示为 450x300px，居中在容器中

旧的错误流程（使用容器坐标）:
用户在显示图片上选择 (50, 50, 200, 100)
-> 错误地相对容器计算: (50/800, 50/600) = (6.25%, 8.33%)
-> 应用到原图: (3000*6.25%, 2000*8.33%) = (187px, 166px)
❌ 结果：裁剪位置完全错误

新的正确流程（使用显示坐标）:
用户在显示图片上选择 (50, 50, 200, 100)
-> 正确地相对图片显示区域: (50/450, 50/300) = (11.1%, 16.7%)
-> 应用到原图: (3000*11.1%, 2000*16.7%) = (333px, 334px)
✅ 结果：裁剪位置准确
```

## 🔧 解决方案

### 架构改进

引入了独立的坐标转换层，负责管理三个坐标空间之间的转换：

```
┌─────────────────────────────────────────────────────────┐
│                   ImageProcessorPage                    │
│                   (组合协调层)                           │
└─────────────────────┬───────────────────────────────────┘
                      │
          ┌───────────┴───────────┐
          │                       │
┌─────────▼─────────┐   ┌────────▼──────────┐
│  ImagePreview     │   │  Controls         │
│  (UI交互层)       │   │  (参数设置层)     │
└─────────┬─────────┘   └───────────────────┘
          │
┌─────────▼─────────────────────────────────────┐
│       useCoordinateTransformer Hook           │ ← 新增
│  (自动管理坐标转换器，监听尺寸变化)          │
└─────────┬─────────────────────────────────────┘
          │
┌─────────▼─────────────────────────────────────┐
│       CoordinateTransformer                   │ ← 新增核心层
│  (坐标空间定义和转换逻辑)                    │
└───────────────────────────────────────────────┘
```

### 新增文件

1. **`utils/coordinateTransformer.ts`** - 坐标转换器核心类
   - `CoordinateTransformer` 类：管理三个坐标空间的转换
   - 提供方法：
     - `containerToDisplay()` - 容器坐标 -> 显示坐标
     - `displayToContainer()` - 显示坐标 -> 容器坐标
     - `displayToImagePercent()` - 显示坐标 -> 图片百分比
     - `imagePercentToDisplay()` - 图片百分比 -> 显示坐标
     - `isPointInDisplayArea()` - 检查点是否在显示区域内
     - `constrainDisplayCrop()` - 约束裁剪框在有效范围内

2. **`hooks/useCoordinateTransformer.ts`** - 坐标转换器 Hook
   - 自动创建和更新坐标转换器实例
   - 监听窗口 resize 和元素尺寸变化
   - 使用 `ResizeObserver` 自动更新转换参数

### 修改文件

**`ImagePreview.tsx`**
- 添加 `imgRef` 引用图片元素
- 集成 `useCoordinateTransformer` hook
- 重写所有鼠标事件处理器，使用正确的坐标转换
- 更新裁剪框渲染逻辑，使用像素定位而非百分比

## 📊 性能优化

1. **缓存机制**：坐标转换器实例被 `useRef` 缓存，避免重复创建
2. **按需更新**：只在容器或图片尺寸变化时更新转换器
3. **防抖处理**：`ResizeObserver` 自动处理快速 resize 事件
4. **精度控制**：裁剪参数保留一位小数，避免过度精度导致的性能问题

## 🔑 核心要点

1. **明确区分三个坐标空间**：容器、显示、图片
2. **所有鼠标交互在显示坐标空间进行**
3. **Store 中保存的是图片坐标空间的百分比**
4. **Canvas 处理时直接使用图片坐标空间的百分比**
5. **坐标转换逻辑独立、可测试、可复用**
